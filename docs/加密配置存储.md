# 结构化配置存储（sqlite3 + 字段级加密）

## 设计

config.json 的**每个字段拆到 sqlite3 表/列**存储，而不是把整个 JSON 加密成 BLOB。
敏感字段保持 `enc:v1:` 密文（字段级加密，由 `LoadConfig` 用 `crypto.aesKey` 解密），
库密码仅用于打开校验（不加密数据本身）。

## Schema

| 表 | 用途 |
|---|---|
| `auth(salt, verifier)` | 库密码校验（PBKDF2-HMAC-SHA256，60000 轮） |
| `meta(k, v, kind)` | 顶层标量：chromePath / chromePort / headless / pluginDir / logLevel / logFile 等 |
| `list_val(section, idx, v, kind)` | 顶层数组：chromeArgs / extensionPaths / chromeExcludeSwitches / _comment |
| `obj_val(section, k, v, kind)` | crypto / ocr / chromePrefs 对象字段；httpTasks 每项一个对象 |
| `banks(id, k, v, kind)` | 银行字段 EAV（每银行一行组） |

`kind` 取值 `str` / `num` / `bool` / `json`，保证 JSON 类型无损往返。
导入→导出已验证与源 JSON **完全一致**（18 个字段、类型、顺序）。

## 密码来源

- 库密码：`NEWRPA_DB_PASS` 环境变量优先，默认 `1qazxsw2A`（用户指定暂定值）
- `auth` 表存 PBKDF2 派生的 verifier；密码不符 → 明确报错并拒绝读取
- 字段级密钥：config 顶层 `crypto.aesKey`（64 位 hex），用于银行密码、OCR 凭据的 `enc:v1:` 解密

## CLI

```bash
newrpa.exe config-import --from config.json --config config.db    # JSON → 结构化 db
newrpa.exe config-export --config config.db --to debug.json       # db → JSON（调试，含密文）
newrpa.exe init --config config.db                                # 生成默认配置库
```

`.vscode/launch.json` 的 `--config` 已全部改指 `config.db` / `config.ccb.db`。
旧 `config.json` / `config.ccb.json` 保留作备份，不删除。

## 备注

- `httpTasks` 是对象数组，存 `obj_val`（每项的 name 作为 key，整项 JSON 作为 v），读取时按 rowid 保序。
- 迁移旧 blob 格式 db：先用旧版 `config-export` 导出 JSON，再用新版 `config-import` 导入即可。
- 根目录 CMakeLists 启用 `LANGUAGES C CXX`，sqlite3.c 以 C 语言编入 core。
