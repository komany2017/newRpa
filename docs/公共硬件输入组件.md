# 公共硬件输入组件（HID 键盘 / HID 鼠标）

> 状态：已落地（2026-11-27）。所有银行插件共用一份实现，编译进 `NewRpaCore.dll`。

## 1. 为什么要公共

原来 `core/src/singleUsbbox/*.cpp` 被每个插件复制一份编进自己的 DLL：

```
plugins/bcb/CMakeLists.txt:  ../../core/src/singleUsbbox/HidKeyBoard.cpp   ← 各编一份
plugins/klb/CMakeLists.txt:  ../../core/src/singleUsbbox/HidKeyBoard.cpp   ← 又编一份
```

后果：代码重复、设备状态各自维护、修一个 bug 要改 N 处；而且各插件的
"找 Chrome 窗口 / 置前台 / 点控件聚焦" 逻辑也是各写一遍，细节已经出现分叉
（KLB 版不按进程名过滤，BCB 版会误置顶 VS Code）。

现在：**硬件层 + 输入策略只编一份**，插件只 `#include` + 链接 `NewRpaCore`。

## 2. 分层

| 层 | 位置 | 职责 |
|---|---|---|
| 设备层 | `core/src/singleUsbbox/hid_box.cpp` | 探测 / 打开 / 收发 65 字节私有帧（自动重连） |
| 输入法层 | `core/src/singleUsbbox/ime_guard.hpp` | 输入前切英文布局，输完切回 |
| 键盘类 | `core/src/singleUsbbox/HidKeyBoard.cpp` | 扫描码段 + 剪贴板段分段发送 |
| 鼠标类 | `core/src/singleUsbbox/HidMouse.cpp` | 闭环相对移动、按键、拟人拖动 |
| **门面** | `core/src/hid/HidInput.cpp` | 窗口聚焦、元素定位、点击聚焦、输入策略（本文重点） |

头文件：

```cpp
#include "newrpa/hid/HidInput.h"        // 门面（绝大多数场景只用它）
#include "newrpa/singleUsbbox/HidKeyBoard.h"  // 需要裸键盘能力时
#include "newrpa/singleUsbbox/HidMouse.hpp"   // 需要标定/拖动时（BCB 滑块）
```

## 3. 门面 API（`newrpa::hid::HidInput`）

```cpp
class HidInput {
    // 设备
    explicit HidInput(cdp::CDPSession* session);
    void SetSession(cdp::CDPSession* session);
    BoxStatus Probe();                    // 只检测不打开
    bool OpenKeyboard(int vid, int pid, int keyDelayMs);
    bool OpenMouse(int vid, int pid);
    void Close();

    // 窗口（静态，不依赖会话）
    static bool FocusChrome(bool maximize, bool topmost);
    static void UnpinChromeTopmost();
    static bool ChromeInForeground();

    // 元素
    bool ElementCenter(const std::string& selector, double& cx, double& cy);
    std::string ActiveElement();
    bool ClickElement(const std::string& selector);      // CDP 合成点击
    bool ClickElementHw(const std::string& selector);    // 真 HID 点击（需 SetMouseOrigin）
    bool FocusElement(const std::string& selector, int attempts = 3);

    // 键盘
    bool TypeHw(const std::string& text, int delayMs, bool clearFirst);
    bool TypeCdp(const std::string& text, int perCharMs);
    int  MaskLength(const std::string& selector);        // 控件已输入字符数
    bool TypeIntoFocused(const std::string& text,
                         const std::string& verifySelector = {},
                         int perCharMs = 120);
    bool PressTab(); bool PressEnter(); bool Backspace(int times);
};
```

## 4. 新银行接入模板

```cpp
// 登录：普通输入框用 CDP 赋值，安全控件用 HidInput
hw_.SetSession(session_.get());
spdlog::info("[XXX] HW box: {}", hw_.Probe().ToString());
if (!hw_.OpenKeyboard(0xC216, 0x0301, 80))
    return "error: hardware keyboard unavailable";

if (!hw_.FocusElement("#passwordControl", 5))     // 点击控件中心 + JS focus 兜底
    return "error: password control not focused";

if (!hw_.TypeIntoFocused(cfg_.password, "#passwordControl"))
    return "error: password not entered";
```

`TypeIntoFocused` 的策略（都是实测踩出来的）：

1. **先发 CDP `char` 事件** —— 不受前台窗口影响，也不会把字符打进别的 Chrome 实例；
2. 按 `MaskLength` 回读控件已呈现字符数，不足则从断点**补输**；
3. 一个字符都没进（控件拒绝合成键盘，如昆仑 iProtect）→ **回退硬件键盘**，再校验一次；
4. 控件不呈现任何可读长度 → 采信 CDP 结果，不回退（避免重复输入）。

## 5. 已封装的坑

| 坑 | 现象 | 组件里的处理 |
|---|---|---|
| 安全控件 `tabindex=-1` | 硬件 Tab 从账号框跳到按钮，密码字符进错元素 | `FocusElement` 按坐标点击控件中心，JS `focus()` 兜底 |
| CDP 合成键盘被拒 | 发送成功但控件星号数为 0 | `TypeIntoFocused` 自动回退 HID |
| 硬件键盘进前台窗口 | 多开 Chrome 时字符打进别的实例 | 输入前 `FocusChrome()`（置前 + 置顶），输完 `UnpinChromeTopmost()` |
| Electron 同名窗口类 | VS Code 类名同为 `Chrome_WidgetWin_1`，被误置顶 | 按进程名过滤 `chrome.exe`，并主动摘掉 `Code.exe` 的 TOPMOST |
| 控件掩码读不到 | 只认 `innerText` 会误判 | `MaskLength` 同时看 `innerText` / `textContent` / `data-len` |

## 6. 现状

- `core/CMakeLists.txt` 编译 `singleUsbbox/*.cpp` + `hid/HidInput.cpp`，随 `NewRpaCore.dll` 导出。
- `plugins/klb`：登录已全部改用 `hid::HidInput`，删掉私有的窗口枚举 / 硬件键盘函数（约 130 行）。
- `plugins/bcb`：窗口查找 / 置前 / 置顶 / VS Code 摘顶改用 `HidInput::FocusChrome` 与 `UnpinChromeTopmost`；滑块标定仍直接用 `HidMouse`（需要 `setOrigin` / `dragRelativeCss`）。
- 实测：KLB `LOGIN_OK user=张丽`；BCB `查询版登录成功: /queryHome`。
